# Obsession · 无广告课表 Android 应用

> 一个从零构建的、**完全没有广告与账号体系**的高校课表应用。
> 起因：原 WakeUp 课程表在被收购后加入开屏广告与搜题模块，安装包从 5MB 膨胀到 30MB，
> 大量老用户流失。这个项目要回到「专注课表、数据不出手机」的形态。

---

## 一、为什么不用 WakeUp 的源码直接改

原版 WakeUp 的 Kotlin 源码曾以 Apache-2.0 协议开源（`YZune/WakeupSchedule_Kotlin`，559 stars），
但**该仓库已被作者删除**，现存副本只来自第三方 fork（`dongguayaya/`、`micro-coder/`）。

代码体检结果（2018 年代码库，距现在 8 年）：

| 组件 | 仓库版本 | 现状 | 影响 |
| --- | --- | --- | --- |
| Gradle | 4.6 | 停更 | 不支持 Java 22，构建直接失败 |
| Android Gradle Plugin | 3.2.1 | 废弃 | 与 Gradle 8 不兼容 |
| Kotlin | 1.3.11 | 差 7 个大版本 | 大量 API 语义已变 |
| `kotlin-android-extensions` | 使用中 | **Kotlin 1.9 已移除** | 118 个文件的界面绑定需全部改 ViewBinding |
| Anko | 0.10.8 | 作者弃坑 | 与新 Kotlin 冲突 |
| `jcenter()` / Bintray | 依赖仓库 | **2022 年关停** | 依赖无法解析 |
| Fabric / Crashlytics | 插件 + API Key | **2020 年停服** | 必须移除 |
| `com.nbsp:library` / `quicksidebar` / `stickyheadersrecyclerview` | — | 仅托管于 jcenter | 无法获取，需替换 |
| minSdk / targetSdk | 18 / 28 | 商店要求 34+ | 无法上架 |

**结论**：改造成本约 2 周以上，且期间写不了一行自己的功能。
因此本项目把原仓库作为**参考件**（`../wakeup-ref/`），不复用其构建体系。

### 从参考件中借鉴的部分

- `utils/ExportUtils.kt` + `schedule/ScheduleViewModel.kt` → `.wakeup_schedule` 文件格式（已兼容实现）
- `widget/CourseView.kt` → 课表网格绘制与连堂布局思路
- `schedule_import/ImportViewModel.kt` → 各类教务系统页面的 DOM 识别特征（正方 / 强智 / URP），
  本项目据此实现了正方新版的解析器（见第三章）

## 二、合规红线

项目的**硬约束**，任何时候不得突破：

1. **不反编译当前商业版（6.x / v6.4.x）APK**。它已是作业帮旗下北京日光轨迹的闭源衍生版本，
   逆向并分发去广告补丁违反用户协议、侵犯著作权，且无法通过任何应用商店审核。
2. **不使用「WakeUp课程表」名称、图标与官方素材**。Apache-2.0 授予的是代码使用权，不含商标授权。
   本项目使用自有名称「Obsession」（包名 `com.obsession.schedule`）与自有视觉。
3. **不使用原作者的签名密钥**。原仓库 `app/build.gradle` 中硬编码了 `keyAlias 'yzune'` /
   `keyPassword '11166511'`，那是原作者的个人签名，必须彻底废弃。
4. **不模拟登录教务系统、不联网抓取课表**。应用只读用户自己另存的本地 HTML 文件，
   全程不发起任何网络请求。模拟登录涉及学校系统的授权边界问题，且 2000+ 所学校的
   解析规则会持续失效，是这类应用 90% 的维护成本来源。让用户在浏览器里自己登录、
   把页面存成文件、App 只负责读文件 —— 两条路都绕开了，还保住了「零网络权限」的设计。
5. 若将来商业化分发，建议就 fork 代码的使用边界咨询一次法务——原作者删除仓库本身，
   可能意味着其已受收购协议约束。

## 三、已实现的功能

### 数据层（Room）

| 实体 | 说明 |
| --- | --- |
| `CourseEntity` | 课程名、教师、教室、星期、起始节次、连堂数、起止周、单双周、颜色、备注 |
| `TimeSlotEntity` | 节次作息表，默认 12 节，可改 |

### 关键实现点

- **单双周判定**：`CourseEntity.activeIn(week)` 统一处理起止周与奇偶周，避免各处重复判断。
- **连堂布局对齐**：`DayColumn` 用「游标推进」算法渲染，一节课跨 N 节时渲染单个
  `rowHeight × N` 的块并跳过后续节点，保证与左侧时间列严格对齐。
- **重叠课程并排**：同一时段冲突的课程经 `groupByOverlap()` 分组后左右分栏、等宽显示，
  每门课都露出课名，右上角标出「N 门」。
  （v0.1.1 之前是「先到先得」，冲突项**被直接丢弃** —— 那是个 bug，用户根本看不到自己有两门课撞了）
- **学期与真实日期**：`SemesterConfig` 存第一周起始日与总周数，课表顶部显示
  「第 3 周 · 9月14日 – 9月20日」，星期栏带日期、今天高亮。
  打开应用**自动定位到当前周**，不再每次从第 1 周翻起。
- **课程配色只取色相**：数据库仍存 ARGB（兼容 `.wakeup_schedule` 与任意自选色），
  渲染时由 `CourseColors.kt` 提取色相 H 重新生成「浅底 + 深字 + 强调条」。
  一套规则同时适配明暗两主题，不必维护两份色板，深色下也不会出现刺眼的课程块。
- **文件兼容**：`ScheduleCodec` 同时支持自有 JSON 格式与 WakeUp 3.x 的 `.wakeup_schedule`
  （实为 5 行 JSON 拼接，依次是时间表信息 / 节次时间 / 课表信息 / 课程基础信息 / 课程详情）。
  字段缺失、颜色非法等情况均可容错降级，不会崩溃。

### 界面

- 周视图课表网格（7 天 × 可变节次），时间列显示节次与上课／下课时间
- 顶部显示**学期名 · 第几周 · 该周真实日期区间**；星期栏带日期，**今天那一列高亮**
- 周次切换（1 – 总周数），打开应用自动停在当前周
- FAB 添加课程；点击课程块编辑／删除
- 编辑器：课程名、教师、教室、星期、起止节次、连堂数、起止周、单双周、8 色可选
- **重叠课程并排**：冲突的课左右分栏，不再是先到先得
- **每节课时间设置**：逐节调整上下课时间，支持增删节次、一键恢复默认
- **学期设置**：学期名、第一周起始日、总周数，带实时预览
- **桌面小组件**：4×2 今日课表 / 2×2 下一节课 / 4×1 简洁条
- 通过系统文件选择器导入／导出课表文件（SAF，不申请存储权限）；
  导入同时支持**教务课表页另存的 HTML** 与本应用导出的备份文件
- 柔光（浅色）/ 墨影（深色）双主题，自动跟随系统

#### 学期设置（v0.2 新增）

菜单 →「学期设置」。三个字段：

- **学期名**：仅用于显示
- **第一周起始日**：用系统日期选择器选。**注意**：选中的日期会被归一到它所在周的周一，
  界面上明确写出这一点（例如选了 9月1日周二，会提示「第 1 周从 8月31日（周一）起算」），
  否则用户会以为算错了
- **总周数**：1–40 周

底部预览卡实时显示第 1 周、最后一周的日期范围，以及「今天是第几周」。
若当天在开学前或已超出学期，会直接说明，而不是夹到第一周或最后一周。

#### 桌面小组件（v0.2 新增）

三个尺寸，均适配深浅色、点击整块打开应用：

- **4×2 今日课表**：列出当天全部课程，**已上过的自动淡化**，正在上的用主色强调
- **2×2 下一节课**：显示「正在上 / 下一节」、时间、课名、教室
- **4×1 简洁条**：一行文字，`14:55  体育（羽毛球） · 体育馆`

两个实现上的取舍：

- **刷新**：`updatePeriodMillis` 最小只能设 30 分钟，靠它刷新意味着改完课表要等半小时。
  因此课程增删改、改作息、导入后都会主动调 `refreshAll()`，并切到 IO 线程执行。
- **状态判定**：作息表没配时时间显示 `--:--`，此时该课一律算「未开始」。
  宁可把它当成即将到来的课，也不要因为解析不出时间就判定成已上过而淡出。

#### HTML 课表导入（v0.2 新增）

**用法**：电脑浏览器登录教务系统 → 进课表查询页 → `Ctrl+S`，保存类型选**「网页，仅 HTML」**
→ 把文件传到手机 → 应用内「导入课表文件」。同一个入口也吃本应用导出的备份文件
（按文件内容自动分派）。

**为什么走文件而不是联网抓取**：不模拟登录、不保存账号密码、不申请 `INTERNET` 权限。
教务系统的授权边界和解析规则的长尾维护是这类应用 90% 的成本来源，
让用户自己登录、App 只读文件，两条都绕开了。

**链路**（都在 `importer/` 包下，纯 JVM 代码，因此能跑单元测试、不必连真机）：

1. **`HtmlTextDecoder` 探测编码**，顺序是「先证据后猜测」：
   BOM → `<meta charset>` 声明 → 严格 UTF-8 试解码 → 退回 GB18030。
   国内教务系统大量是 GB2312/GBK，一律按 UTF-8 硬读会得到「读得出内容但内容全错」的乱码 ——
   这是最隐蔽的一类 bug，所以单独做了一层探测。
2. **`ZhengFangNewParser.detect()` 按 DOM 特征路由**：`#kblist_table` → 正方新版（列表模式）；
   `kbgrid_table*` → 正方新版（课表模式）；`#Table1` → 正方旧版；`#kbtable` → 强智；
   `bordercolordark` → URP。
3. **解析**。两张表**各写一套**提取逻辑，因为字段位置根本不同：
   列表模式的标签在正文里（`周数：`、`上课地点：`、`教师 ：`），
   课表模式的标签在 `title` 属性上（`<span title="节/周">` 后跟值）。
   网格模式不走「还原成列表」那条路 —— td 的 `rowspan` 只表示格子占几行，
   同一格里可能叠着好几门课，硬还原容易错位。
4. **`ImportPreviewDialog` 先出预览**：来源、文件编码、学期名、逐条课程、未导入项。
   用户核对后才入库，并可选「替换」或「追加」。解析不可能 100% 准确，
   让用户把关十秒，比让他过几天发现课表里混进错课再回头查要省事得多。

**已适配**：正方教务新版。用真实导出页（示例大学，2026-2027 学年第 1 学期）验证，
22 条课程记录全部解析正确，列表模式与课表模式**交叉验证结果一致**。

**未适配**：正方旧版 / 强智 / URP 能识别出来，但会明确提示「需要样本」，
不做「尽力解析」。理由：解析错、但看起来正常的结果，比明确说不支持更危险 ——
用户会在预览里被一堆貌似合理的错课骗过去。

**踩过的坑**（均已写成回归测试，见 `app/src/test/`）：

- `教师 ：`（冒号前有空格）与教室之间只隔一个空格，最初的正则把两者圈进了同一个字段
- 同一格里可能叠着两门**不同周次**的课（如软件工程 1-12 周 + 现代通信技术 13-14 周），
  那门课所在的 `tr` **没有节次单元格**，取格时若只看第一个格子就会漏课 —— 实测漏了 22 条里的 2 条
- jsoup 的 `text()` 会把连续空白压成单个空格，而课表模式下校区名与教室名正是靠**两个空格**分隔的。
  读教室必须用 `wholeText()`，否则「示例大学  图书馆303」会粘成一个字段
- 表格底部的「实践课程：操作系统课程设计…/15周」没有星期和节次，落不进数据模型，
  如实报告为「未导入」，不静默丢弃
- 不连续的周次（`1,3,5-7周`）要拆成多条记录 —— 数据模型里 `startWeek`/`endWeek` 是一对，
  不拆就只能丢数据
- 导入后若最晚周次超出当前「总周数」，**自动放宽总周数**（只放宽、不缩小），
  否则第 15 周以后的课在界面上根本翻不到
- 导入只替换**课程**，不动**作息**（每节课几点到几点是用户自己配的，教务页面里没有这个信息）

#### 每节课时间设置（v0.1.1 新增）

入口有两个，都能到：**右上角菜单「每节课时间」**，或**直接点课表左侧的时间列／左上角齿轮**。

- 节次数可自由增减（1–20 节）；删除中间某一节后，后面的节次自动前移重新编号
- 输入只认数字，冒号自动补：敲 `800` → `08:00`，敲 `0800` 也 → `08:00`，不用去找冒号键
- 「加一节课」会按上一节下课时间 + 10 分钟休息、45 分钟课时自动推算，不必手填
- 保存前做两级校验：
  - **需修改**（阻断保存）：时间格式不合法、下课时间早于或等于上课时间
  - **提醒**（不阻断，允许保存）：相邻两节时间重叠——这属于用户的自由，只提示不强制
- 若当前课表有课程排到第 13 节而作息只留了 12 节，会明确告知多出的行仍会显示但不再有上下课时间，
  不会悄悄隐藏课程

保存采用**整表清空重写**而非逐行更新。原因是删掉中间某节后后续节次会整体前移，
逐行 `upsert` 会在表里留下编号重复或空洞的行。

### 权限

v0.3 起新增**唯一一条联网权限**：

| 权限 | 用途 | 边界 |
| --- | --- | --- |
| `INTERNET` | **仅**内置浏览器导入教务课表用 | 应用自身不发任何请求；登录密码不经过本应用；关闭导入页立即清除 Cookie 与 LocalStorage |
| `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | 系统自动生成的内部标记（`registerReceiver` 的 NOT_EXPORTED 保护），不是真权限 | — |

除此之外没有存储权限、没有定位。课表、作息、背景图引用全部存在本机
（Room + SharedPreferences + SAF 持久化 URI），天然不存在隐私外泄路径。

## 四、技术栈

```
Kotlin 2.0.20          Compose BOM 2024.09.00
AGP 8.5.2              Room 2.6.1 + KSP
Gradle 8.9             Gson 2.11.0（仅在文件编解码用）
                       Jsoup 1.16.1（仅用于解析本地 HTML，不联网）
compileSdk 34 / minSdk 24 / targetSdk 34
```

> minSdk 定为 24 的代价：`java.time` 需要 API 26 或 core library desugaring。
> 为两个日期函数引一个注解处理器不划算，因此学期日期计算全部走 `java.util.Calendar`。

选 Compose 而非原版的 XML + 契约式绑定，理由：原版重度依赖已被移除的
`kotlin-android-extensions`，而 ViewBinding 迁移 118 个文件成本极高；Compose 反而代码量更少。

## 五、构建与运行

### 方式 A：Android Studio（推荐，日常使用走这条）

1. **打开项目**：Android Studio → `Open` → 选 `E:\study\class\cleantable`
   （必须是项目**根目录**——里面有 `settings.gradle.kts` 的那层；选成 `app` 子目录会同步失败）
2. **首次 Gradle Sync**：打开后自动开始，右下角进度条走完即可。
   所有依赖已在本地 Gradle 缓存（`<本机用户目录>\.gradle\caches`），正常情况**不需要联网**。
   若报「Could not resolve / 下载超时」：`File → Settings → Appearance & Behavior →
   System Settings → HTTP Proxy → Manual`，Host `127.0.0.1`、Port `1526`
   （端口以环境变量 `http_proxy` 当前值为准），确定后重新 Sync。
3. **手机开 USB 调试**：设置 → 关于手机 → 连点「版本号」7 次 → 返回 →
   系统 → 开发者选项 → 打开「USB 调试」。
4. **连接并运行**：数据线连电脑（要能传数据的线）→ 手机弹「允许 USB 调试」→
   始终允许 → 确定。AS 顶部设备框出现手机型号后，点绿色 ▶（Run 'app'）——
   自动构建、安装、启动。
5. **只出 APK 文件**（发给同学用）：`Build → Build Bundle(s) / APK(s) → Build APK(s)`，
   完成后点右下角通知的 locate，产物在 `app/build/outputs/apk/debug/`。

常见问题：
- 设备下拉为空 → 换一根数据线；或下拉手机通知栏，把 USB 用途改成「传输文件」
- Run 报 `INSTALL_FAILED_*` → 先在手机上卸载旧版 Obsession 再点 ▶
- Sync 报 JDK 错误 → `Settings → Build Tools → Gradle → Gradle JDK` 选 Embedded JDK (jbr-21)

### 关于 gradlew（Git Bash 用户必读）

本项目的 `gradlew` 已针对 Git Bash（MINGW64）做过修补。原因：从旧项目复制来的
gradle-wrapper 脚本只判断 `$cygwin`，不判断 `$msys`，在 Git Bash 下不会把 classpath
转成 Windows 路径，会报 `ClassNotFoundException: org.gradle.wrapper.GradleWrapperMain`。

修补内容：

```diff
-if $cygwin ; then
+if $cygwin || $msys ; then
```

若在别的机器上仍遇到该报错，可临时绕过：

```bash
java -classpath 'E:\path\to\project\gradle\wrapper\gradle-wrapper.jar' \
     org.gradle.wrapper.GradleWrapperMain assembleDebug
```

更彻底的做法是用现代 Gradle 重新生成 wrapper：`gradle wrapper --gradle-version 8.9`。

### 明确不做

- 任何形式的广告、开屏、弹窗推广
- 账号注册与云端同步（避免把「几点在哪栋楼上课」这类行踪数据交给服务器）
- 拍照搜题、社交、校园跑腿等与课表无关的模块

### 待评估

- **更多教务系统的解析器**。目前只适配了正方新版。加一套的成本并不高 ——
  解析器是 `importer/` 下的独立模块，识别特征与提取逻辑各自封闭，
  实测加一套约几十行代码 + 一份样本夹具。瓶颈始终是**样本**而不是代码。
  若将来要覆盖大量学校，可行的方向是把解析规则改成可热更新的配置
  （原版 WakeUp 与 Dawn-Course 都这么做），而不是继续硬编码进 APK。

## 七、给测试同学的验收要点

本项目的测试用例可由以下维度展开（对应阶段一「测试准备」）：

**功能正确性**
- 单双周课程在第 1/2/3/16 周是否显示正确
- 连堂课程（step ≥ 2）网格高度是否与左侧时间列对齐
- 跨周课程（如 3-9 周）在第 2 周与第 10 周是否隐藏
- 起止周填写颠倒（如 9 到 3）是否被自动纠正

**导入导出**
- 自有格式导出后再导入，数据是否一致
- 导入 WakeUp 3.x 的 `.wakeup_schedule`，课程名与颜色是否还原
- 导入空文件、非课表 JSON、被截断的文件，是否给出可读提示而非崩溃
- 导入 200+ 门课程的性能表现

**HTML 课表导入（v0.2 新增）**
- 用自己学校的课表页另存 HTML 导入，逐条核对课程名 / 星期 / 节次 / 周次 / 教室 / 教师
- 与教务页面上的课表逐格比对，确认没有漏课（**重点看同一时段有两门不同周次课的格子**）
- 重复导入同一文件：选「替换」应不产生重复记录；选「追加」应明确产生重复（这是预期行为）
- 导入后日程表最晚周次若超出原「总周数」，检查总周数是否被自动放宽、能否翻到最后一门课
- 导入一只含课表模式（或只含列表模式）的页面，检查另一条解析路径是否兜住
- 把编码改成 GB2312 另存后再导入，课程名是否仍可读（重点项：这是最容易出乱码的地方）
- 导入非课表 HTML（例如一张普通网页）应给出可读提示，而不是崩溃或导入空课表
- 导入强智 / 正方旧版的页面，应提示「需要样本」而不是导入一堆错课
- 预览里点「取消」后，课表应完全不变

**作息时间设置（v0.1.1 新增）**
- 输入 `800` / `0800` / `8:00` / `8：00`（中文冒号）是否都能得到 `08:00`
- 退格删除时时间是否被搅乱：从 `08:00` 删到 `08:0` 应保持 `08:0`，不能变成 `00:80`
- 下课时间填得早于上课时间 → 保存按钮应置灰，并标红该行
- 相邻两节时间重叠 → 应只提醒、允许保存
- 删掉中间第 5 节后，第 6 节及之后是否前移重新编号，且课程块与行号对应关系仍然正确
- 节次数减到小于「已排课程的最大节次」时，多出的行是否仍显示课程（预期：仍显示，只是没有时间）
- 「加一节课」推算出的时间是否为「上一节下课 + 10 分钟」，时长 45 分钟
- 点「恢复默认」后不保存直接退出，原作息应保持不变
- 保存后杀掉进程重进，作息是否持久化

**边界场景**
- 12 节全排满时的滚动与渲染
- 第 30 周、第 1 周的上下周按钮禁用状态
- 深色模式下 8 种课程颜色的文字对比度是否可读
- 同一时段两门课程的冲突表现

**兼容性**
- Android 7.0 / 10 / 14 三档
- 小屏（720p）与大屏（1440p）、折叠屏
- 系统字体放大到 1.3 倍后布局是否错乱
