Obsession v0.4.1 修复方案 demo

两个问题：① 小组件在单节课（及重新放置后）显示「加载中」；② 教务导入解析失败。以下先给根因，再用可交互 demo 展示修复后的行为。确认后我才动代码。

根因 1小组件「加载中」＝渲染崩溃，与课程数量无关

  • 组件渲染用 runBlocking 查数据库，但 Room 未允许主线程查询 → 系统投递组件更新时（主线程）直接抛异常 → 启动器永远停在「加载中」。
  • 而午夜闹钟 / 应用内改课表走后台线程，能渲染成功 —— 所以有时又「自己好了」，「下一节课」恰好最近一次刷新走的是后台。
  • 你单节课测试时重新添加了组件，正好触发主线程崩溃，与 1 节课只是时间巧合。
  • 连带：刷新循环无异常隔离（一个组件崩连累其余）；未设学期起始日时周数计算溢出（≈2945 周），课程被全部误过滤。

根因 2浏览器只抓主文档，拿不到 iframe 里的课表

  • 当前只取主文档 outerHTML：课表在 iframe 内时抓不到 → 「解析失败 / 0 门课」。
  • 正方教务是 SPA：页面内跳转不触发「加载完成」事件，自动识别失灵；异步渲染时探测也偏早。
  • 采纳你的思路：页面存为临时 HTML → 走与文件导入完全同一解析管线 → 导入后删除；失败时样本保留供导出发我。
  • 真正救活解析的是：逐 frame 提取 + SPA 路由探测 + 延迟重试（文件只是更稳的壳）。
