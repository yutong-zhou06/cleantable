桌面小组件「静态快照」重构 · v0.4.3 方案演示

Obsession · 2026-09-16 · 仅供方案审核，未改任何工程代码

一、为什么换思路

v0.4.2 已经把渲染异常兜住，但真凶的异常栈通过 logcat 抓不到（崩溃发生在启动器进程侧或被系统吞掉）。 与其继续在「动态拼装 RemoteViews」这条路上猜，不如换到兼容性最高的做法： 组件不再让启动器拼装任何布局，只显示一张我们画好的图。 启动器端只剩一个 ImageView —— RemoteViews 里最古老、最稳定的 API，没有任何可崩的拼装环节； 而且画图过程发生在我们自己的进程里，出了异常可以直接在应用内弹窗给你看，彻底不需要 logcat。

二、新管线

① 应用内点「一键更新」主页菜单新增入口
（也可自动触发）
→
② Canvas 画快照把今天的课表按屏幕密度
画成一张位图
→
③ 存入应用私有目录每张课表 × 每种尺寸一份
轻量缓存
→
④ RemoteViews 只放 ImageViewsetImageViewBitmap
系统级最稳 API
→
⑤ 桌面显示启动器零拼装
没有可崩的环节
任何一步失败：异常被应用捕获并直接显示在「一键更新」的结果面板里（错误原文 + 失败的是哪个组件）， 组件退回空布局兜底 —— 你不需要连电脑抓日志，手机上就能看到出错原因。

四、自动刷新时机（不只是手动）

  • 应用内修改/增删课程后 → 自动重画并推送
  • 跨天（0 点闹钟，v0.3 已有）→ 重画「今天」的内容
  • 打开应用时 → 静默校对一次，防止错过的事件
  • 桌面调整组件大小 → 系统回调尺寸变化，按新尺寸重画
  • 切换浅色/深色主题 → 按当前主题重画对应配色
  • 切换多课表 → 跟随「当前查看的课表」重画

五、取舍与边界（如实说明）

  • 文字是画进图里的，不跟随系统字体大小设置——按屏幕密度换算，正常手机上清晰度无损
  • 组件内的行不能单独点击，整卡点击打开应用（和现在一致）
  • 「下一节课」「简洁条」也一并换成快照渲染，三个组件行为统一、代码同一条管线
  • 位图缓存放在应用私有目录，每种尺寸一份、覆盖更新，不额外占空间（单张约几十 KB）
  • 万一快照绘制也失败 → 自动退回现有的 XML 空布局兜底，永不显示「加载中」

六、审核要点

1. 快照的视觉样式是否满意（第三区右侧可切组件/主题/时间/课程数）？
2. 「一键更新」的入口位置（主页右上菜单）与结果面板形式是否 OK？
3. 第五节列出的取舍你是否接受？确认后我再动工程代码。
